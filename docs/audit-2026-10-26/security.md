# Capitol Receipts: security, backend, database and payments register

Audit date: 2026-10-26. This audit was read-only. Nothing was written to the database, no accounts were created and no payments were made. Live checks were limited to 3 `curl -sI` requests.
Scope: repo `/home/claude/app` (121 commits on main), Supabase project `hxgckcriehvrolwnabpd` (read-only SQL and advisors), and the live hosts app., www. and admin.capitolreceipts.com.

## Summary
- **Critical:** none found.
- **High (2):**
  - SEC-01: the subscription `source` field gets out of step with the actual billing provider. This can stop account deletion from cancelling a Stripe subscription.
  - SEC-02: the admin portal has no MFA.
- **Medium (7):** SEC-03 to SEC-09.
- **Low:** several, plus many Pass items.
- **Pass:** the database layer is in good shape. RLS is on for every table, policies are scoped to `auth.uid()`, SECURITY DEFINER functions are locked down, and the public forms use column-level grants. No secrets were found in the working tree or in git history.

| SEC-01 | Several writers of `subscriptions` ignore or overwrite `source`. | SEC-04 | Third-party scripts load without Subresource Integrity, including on the admin page. | Web / admin | Medium | Fail | `admin.html:76` loads `cdn.jsdelivr.net/npm/@supabase/supabase-js@2.45.4/dist/umd/supabase.js` with no `integrity`. `app/js/account.js:8` loads supabase.min.js the same way. `app/js/hist.js:41` loads fflate@0.8.2. | SEC-05 | Stripe webhook applies `customer.subscription.*` payloads in the order they arrive, with no ordering guard. | stripe-webhook | Medium | Fail | `stripe-webhook/index.ts:66-81` uses `ev.data.object` as-is. | SEC-06 | RevenueCat webhook accepts sandbox events in production and has no ordering or duplicate guard. | appstore-webhook | Medium | Fail | `appstore-webhook/index.ts:121`: the comment says sandbox purchases count, and `e.environment` is never checked. | SEC-07 | Password reset has no "set new password" step. | Web auth | Medium | Fail | `app/js/account.js:77` sends the reset email. `account.js:15` `onAuthStateChange` ignores the `PASSWORD_RECOVERY` event. | SEC-08 | `/api/db` lets anyone run arbitrary PostgREST queries on the allowlisted tables. | SEC-09 | Account deletion leaves data with payment and auth providers, and the email match uses wildcards. | account fn | Medium | Fail | `account/index.ts:51-56`: the app's own tables are cleaned (push_devices, apple_tokens, user_prefs, alert_log, billing_email_log, subscriptions), and FKs to auth.users are `ON DELETE CASCADE` (verified).
